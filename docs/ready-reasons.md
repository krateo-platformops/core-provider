# Condition reasons of a composition

Generated by `go test ./internal/composition/ -run TestReadyReasonTableIsCurrent` in
go/composition-dynamic-controller, with `UPDATE_READY_REASONS=1` to rewrite it. Do not edit by hand.

Every reason a composition's conditions can carry: `Ready` (core-provider#515), and `Synced`,
`ChartRenderable`, `RBACComplete` and `ApiResolved` (#528). The composition-dynamic-controller builds
every one of these conditions through `internal/conditionreason`, whose values cannot be constructed
elsewhere, and a test refuses any other construction in the module. The unstructured-runtime rows
are written by the runtime on the same compositions. `ApiResolved` appears only on a composition
whose CompositionDefinition has an apiRef.

The set is CLOSED except for one row, marked: an `ApiResolved=False` refusal carries authn's OWN
reason, passed through as authn sent it (e.g. `NoMapping`, `AudienceMismatch`, `MissingBearer`), so its
strings are authn's and not listed one by one.

- **status** is the status the reason is always written with.
- **parent verdict**, on `Ready` rows only, is how this controller's child rollup reads a composition
  child carrying it, computed by `krateoReady`. `converging` keeps the parent `Ready=False/Creating`.
  The rollup reads only `Ready`, so other conditions show `—`.
- **expected to clear** is how long the reason should last: `steady` (the end state), `timer` (bounded by a
  named timer: wait for it), `next pass` (re-read after the next reconcile) or `indefinite` (lasts until
  something outside the controller changes). Each timer is printed with its default and the
  environment variable that overrides it, so a deployment can differ.
- **written by** names the code that writes it.
