# Condition reasons of a CompositionDefinition

Generated by `go test ./internal/cdreason/ -run TestCDReadyReasonTableIsCurrent` in go/core-provider,
with `UPDATE_READY_REASONS=1` to rewrite it. Do not edit by hand. A composition's reasons are in
[ready-reasons.md](ready-reasons.md); the two are separate sets, and a reason string can appear in both.

Every reason a CompositionDefinition's `Ready` and `Synced` can carry. core-provider builds every Ready
condition through `internal/cdreason`, whose values cannot be constructed elsewhere, and a test refuses
any other construction in the CompositionDefinition controller. The provider-runtime rows are written
by the managed reconciler on the same objects. The set is CLOSED. The other condition types a
definition carries (ControllerActive, SchemaFullyEnforced, SpecSchemaCurrent and the rest) are not
listed here.

- **status** is the status the reason is always written with.
- **parent verdict**, on `Ready` rows only, is how a parent composition's child rollup reads a
  CompositionDefinition carrying it. A definition IS such a child: installer's umbrella composition
  renders most of a cluster's definitions, and the composition-dynamic-controller's rollup reads every
  `*.krateo.io` child's Ready (`krateoEval`). core-provider declares it, and the cdc's
  `TestCompositionDefinitionReasonsRollUpAsDeclared` reads this file and fails when `krateoEval`
  disagrees with a row. `converging` keeps the parent `Ready=False/Creating` while it lasts, and
  `Creating` has no deadline of its own. The rollup reads only `Ready`, so `Synced` shows `—`.
- **written by** says when it is written.

| condition | reason | status | writer | parent verdict | written by |
|---|---|---|---|---|---|
| Ready | `Available` | True | core-provider | healthy | Observe: the CRD serves the version and is Established, and the controller Deployment has rolled out and is available for its current generation (Diego, 2026-11-16); on a follower, the shared controller, and the message names the definition that owns it |
| Ready | `ScaledToZero` | True | core-provider | healthy | Observe: the controller is at 0 replicas and the definition opted into scale-to-zero (#393); it wakes on the first instance |
| Ready | `Creating` | False | core-provider | converging | Observe: a first pass (seeded before any work), the CRD does not exist yet or is not yet Established, the controller Deployment is absent or rolling out, an update pending with no earlier verdict to keep (#395), or the definition has just become the controller's owner (#387). Update: the pass that switches status to a new version, until Observe looks at its controller |
| Ready | `Unavailable` | False | core-provider | failed | Observe: the chart cannot be read, the controller has 0 replicas without opting into scale-to-zero, the controller Deployment gave up its rollout (ProgressDeadlineExceeded) or lost availability after a completed one, or adding the served version is refused (a held version, no room); the message says which, and for lost availability ends with the first not-ready pod's cause, e.g. "; pod <name>: restarting (last exit: Error)" (#559) |
| Ready | `RemoteChartUnreachable` | False | core-provider | failed | remote seed: the chart's URL is cluster-local to the management cluster, so the remote target cannot fetch it |
| Ready | `SchemaDefaultContradiction` | False | core-provider | failed | Observe: a `default` in the chart's values.schema.json that crdgen carries into the CRD fails its own subschema, so no CRD is generated; the message names each JSON pointer (plumbing#205). Nothing is applied, and a definition that worked before keeps serving its last CRD |
| Ready | `ValuesSchemaMissing` | False | core-provider | failed | Observe: the chart has no values.schema.json at its root, so no typed CRD can be generated and nothing is applied; the message names the chart (#566) |
| Ready | `DerivedNameTooLong` | False | core-provider | failed | Observe: a name derived from the chart's name and Chart.yaml version does not fit Kubernetes' limits: the CRD version is not a DNS-1035 label, the controller Deployment's name (also its selector label) is over 63 characters, or, with cdc.metrics.enabled, the controller Service's is; the message names each name, its length and the problem. Nothing is applied, and a definition that worked before keeps what it has (#588) |
| Ready | `Deleting` | False | core-provider | converging | Delete: the definition is being deleted |
| Ready | `NotObserved` | Unknown | provider-runtime | unevaluated (rolls up as healthy) | Connect or Observe returned an error not marked ReadyAssessed (for example, the controller Deployment could not be read); the error is on Synced |
| Ready | `Creating` | False | provider-runtime | converging | the create path: written with every Create outcome, success or failure (the error, if any, is on Synced) |
| Ready | `Deleting` | False | provider-runtime | converging | the delete path, and an Observe error on a definition being deleted |
| Synced | `ReconcileSuccess` | True | provider-runtime | — | the pass completed |
| Synced | `ReconcileError` | False | provider-runtime | — | the pass failed (message: the error); with Ready=False/SchemaDefaultContradiction it reads "observe failed: " followed by Ready's message |
| Synced | `ReconcilePaused` | False | provider-runtime | — | krateo.io/paused is set; Ready is left as it was |
